# 知识笔记语义缩放可视化系统

把 Obsidian vault 里指定范围的笔记，做成一张**像地图一样按缩放级别切换显示粒度**的图：
滚轮放大 → 看到更细的知识结构，滚轮缩小 → 收拢回学科总览。

深度轴一共 **10 层**，从最粗到最细：

```
顶层文件夹 → 中间文件夹 → 子文件夹 → 更深子文件夹 → 笔记(.md) → 一级标题 → 二级 → 三级 → 四级 → 五级标题
```

文件夹、笔记、标题都是人为规定的**存储结构**；这张图关心的是知识内在的**包含关系**与**连接关系**，
所以包含关系画成嵌套圆布局（circle packing：子圆严格落在父圆内部，不画成一堆线），
连接关系画成细线。

产出是**单文件 HTML**，双击就能在 Chrome 里打开，不需要服务器、不需要联网。
一共产出两份，按 scope 分（见 §1）：

| scope | JSON | HTML | 说明 |
|---|---|---|---|
| `private`（默认） | `dist/graph.json` | `dist/knowledge-graph.html` | ★ 双击这个；**不上网** |
| `public` | `dist/graph.public.json` | `dist/knowledge-graph.public.html` | 与 Quartz 站点共用同一套范围；是否上站见 §1 |

`private` 那份**故意沿用旧文件名**：双击 `dist/knowledge-graph.html` 的习惯不用改。
**渲染是自绘的 Canvas2D，没有用任何第三方图形库**（早期版本用 Cytoscape，已整体替换，
原因见 `HANDOFF.md`）。

```
python build.py scan      # 扫描 vault，打印纳入/排除与链接统计
python build.py suggest   # 挖掘候选边 → candidates.yaml（待你审核）
python build.py build     # 生成 dist/graph.json 与单文件 HTML
python build.py verify    # 跑自动校验（每次改动后都要跑）
python build.py watch     # 笔记改动后自动重建（2 秒轮询，挂在旁边即可）
python build.py all       # scan + suggest + build

# 每条子命令都能带 --scope private|public|all（简写 -s）；不带 = scopes 里排第一的那份（private）
python build.py build  --scope public     # 只建公开那份
python build.py verify --scope public     # 只校验公开那份
python build.py scope  --scope public     # 打印公开那份的镜像清单（stdout 上只有 JSON）
```

`scope` 是喂给同步脚本的机器接口（vault 里的 `quartz-setup/sync.ps1` 把它直接交给
`ConvertFrom-Json`），想给人看范围概览请用 `scan`。`build --scope all` 两份都建；
`watch` 一次只能盯一份（`--scope all` 会被拒绝）。

只用到一个第三方依赖：`PyYAML`（`pip install pyyaml`）。Python ≥ 3.9。

回归验证：

```
python build.py verify      # 数据侧断言
python browser_check.py     # 浏览器侧 162 项断言（Playwright + 本机 Chrome，自动截图）
```

## 1. 改「公开哪些文件夹和笔记」

**唯一入口是 vault 里那份「公开范围真源」**，本项目只负责读它：

```
D:/obsidian_vault/hush-ob-bucket/quartz-setup/public-scope.yaml
```

它放在 vault 里（所以会被 obsidian-git 一起备份），**Quartz 站点镜像哪些目录、公开版图谱扫哪些、
私有图谱扫哪些，三件事共用这一份** —— 以前那种「同步脚本里一份目录清单、`config.yaml` 里再一份
`include`」的双份维护已经删掉了。想改范围就改这个文件，不用碰任何脚本或 Python 代码。

```yaml
# content: 内容目录。scopes 决定它出现在哪几处：
#   public  → 镜像进 quartz-site\content\，并且进公开版图谱
#   private → 只进自留的私有图谱，站点完全看不到
content:
  - from: "Science and Tech"
    scopes: [public, private]
  - from: "Projects"
    scopes: [public, private]
  - from: "Logs/Study log"        # as 是落地名：站点上落 content\Study log\，
    as: "Study log"               # 公开图谱里也直接以 Study log 为根（不套一层 Logs）
    scopes: [public]
  - from: "Economy and Finance"
    scopes: [private]
  # …Medical and Health / Literature History Philosophy / Interest 同理，都是 private

assets:                           # 只镜像进站点、不进图谱（附件本来就不会变成节点）
  - from: "Attachment"
    scopes: [public]

exclude:                          # 两份范围共用的黑名单，优先级高于 content / assets
  - "**/private/**"
  - "**/.minimax/**"
  - "**/draft*"                   # 文件名含 draft 的一律排除
  - "**/*.excalidraw.md"
  - "**/.trash/**"

publish_graph: false              # 公开图谱 HTML 要不要真的发到站点上（理由见本节末尾）
exclude_notes: []                 # 逐篇排除：写笔记名（不带 .md）或 vault 相对路径
```

`as:` 只改**落地名**（站点上的目录名、图谱里的根名），笔记的真实 vault 路径不变：图谱节点里的
`path` 字段仍是 `Logs/Study log/…`，所以「在 Obsidian 打开」按钮照旧能用（`kg/scan.py` 做前缀
重映射，`kg/graph.py` 的别名索引让按真实路径写的 `[[Logs/Study log/xxx]]` 仍然解析得到）。

改完跑 `python build.py build`（或带上 `--scope public` / `--scope all`）。想先确认范围对不对，
跑 `python build.py scan`（默认那份）或 `python build.py scan --scope public`
（下面这份输出是 **2026-10-16 08:37** 那批 payload 的**示例快照**，vault 一改就漂，
以你自己跑出来的为准）：

```
[纳入范围]  vault 内 .md 共 137 篇，纳入 111 篇，排除 26 篇     ← private（默认）
[层级]      文件夹 35 个，最大深度 5
[深度分布]  笔记所在层：{2: 10, 3: 42, 4: 55, 5: 4}
[链接]      [[链接]] 总数 758
  附件链接         █████████████████████··· 666
  笔记→笔记        █······················· 46
  自链接          █······················· 44
  解析失败         ························ 2   ← [[My tech log]]、[[- 大脑-控制框图映射.html]]
[标题]      共 3412 个，平均 30.7 个/篇
```

同一份真源的 **public** 那份是：`.md` 纳入 91 篇（排除 46）、文件夹 23 个、标题 3404 个、
附件链接 656 条。两份共用的 `exclude` 规则一致，差别只在 `content:` 里各条的 `scopes`。

附件链接（指向 png/pdf 等）会被丢弃，不进图。

**两份产物的区别**：`private` 是自留版（6 个学科目录全量，只在本地），`public` 与站点共用同一套
范围（3 个顶层根：`Science and Tech`、`Projects`、`Study log`）—— 注意 `Logs/Study log` 只进
public，所以 private 图里没有它。产物固定叫：

| scope | JSON | HTML | 谁来建 |
|---|---|---|---|
| `private` | `dist/graph.json` | `dist/knowledge-graph.html` | `sync-graph.ps1`（每 30 分钟跑 `build --scope all`，两份本地产物都在这儿出） |
| `public` | `dist/graph.public.json` | `dist/knowledge-graph.public.html` | 同上；另外站点侧 `quartz-setup\sync.ps1` 只在 `publish_graph: true` 时**再重建一次**并上站 |

`private` 的那两个文件名是**故意不动的旧名字**：它是主人日常双击打开的那一份，
换名字等于把使用习惯打断。所以读文档时别默认「`graph.json` = 全部」——它只含 private 范围。

**public 那份会不会上网？** 由 `public-scope.yaml` 的 `publish_graph` 决定，**默认 `false`**：
`quartz-setup/sync.ps1` 只有在它为 `true` 时才把 `knowledge-graph.public.html` 复制进站点
`content/` 并发布到 https://xidianhush.github.io/knowledge-graph.html 。默认关闭是一笔算过的账：
那份 HTML 约 8.7 MB（示例快照 2026-10-17 00:07，即 `dist/` 的生成时间），而站点仓库近 60 天实测 144 次提交
（≈ 2.4 次/天，最后一次 2026-10-15 10:47:42 +0800），每次都提交一遍就是
8.7 MB × 2.4 × 365 ≈ **7.6 GB/年**，而 GitHub 对仓库体积的建议上限约 1 GB、Pages 发布产物也
约 1 GB —— 撑不住。所以默认只在本地产出，范围规则与站点完全一致。

## 2. 与笔记保持同步

笔记会一直改，所以图必须能自动跟上。三种方式，按需选：

| 方式 | 命令 | 适用 |
|---|---|---|
| 手动 | `python build.py build` | 改完立刻看效果（= private 那份；公开那份加 `--scope public`） |
| 实时监听 | `python build.py watch` | 开发/整理笔记时挂在旁边，存盘即重建（2 秒轮询） |
| 定时任务 | `sync-graph.ps1` | 平时后台每 30 分钟重建一次，无需开着终端 |

`sync-graph.ps1` 是给 Windows 计划任务用的包装脚本，它做四件事：

1. **防重入**：`sync-graph.lock` 存在且 2 小时内没结束就 skip（上一次还在遍历 vault）。
2. **确认 `python` 在 PATH 上**，否则写一行 `sync FAILED: python not on PATH` 并退出。
3. **强制 UTF-8 输出编码**：`build.py` 输出含中文，不改会在日志里变乱码。
4. **跑 `python build.py build --scope all`**（两份本地产物都在这儿出），把输出最后 4 行 +
   exit code 追加进 `sync-graph.log`。
5. **裁剪日志**：只保留最近 400 行。

它**只重建 `dist/`，不碰 vault 里的任何笔记，也不做任何 git 操作**（vault 由 obsidian-git 自己备份）。
`.log` / `.lock` 都在 `.gitignore` 里。

> 💡 **为什么是 `--scope all`（两份都在这儿建）**：private 是自留的那份，public 是站点要用的
> 那份，但两份都只是本地文件。站点侧的 `quartz-setup\sync.ps1` 平时只镜像笔记，
> **只有在 `publish_graph: true` 时才会自己再建一次 public 并把它发上站**，
> 免得两个计划任务各自把整张图重建一遍（见 §1 的体积账）。

注册计划任务（**请自己确认后执行**，每 30 分钟一次，在 :07 和 :37 触发）：

```
schtasks /Create /TN "Knowledge Graph Auto Sync" /SC MINUTE /MO 30 /ST 00:07 /RL LIMITED /F /TR "'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe' -N
oProfile -ExecutionPolicy Bypass -File 'D:\obsidian_vault\knowledge-graph\sync-graph.ps1'"
```

> 为什么是 :07/:37：机器上已有的 `Quartz Site Auto Sync` 是每 30 分钟从 :24 起算（:24/:54），
> 两个任务都遍历同一个 vault，错开 17 分钟避免撞车。

> ⚠️ **注册完还要再做一步**：`/Create` 默认写入 `DisallowStartIfOnBatteries=true` +
> `StopIfGoingOnBatteries=true`。笔记本只要在用电池，这条任务就**一次都不会跑**——
> 而症状是 `/Run` 返回「已尝试运行」、属性里 `上次结果: 0`，看着像成功。
> 注册后照「图谱没更新，怎么查」一节里的那段 PowerShell 把两条电池限制关掉。

取消：`schtasks /Delete /TN "Knowledge Graph Auto Sync" /F`

浏览器里已经打开着旧页面时，重建不会自动刷新——**重新双击一次 HTML 即可**（单文件，没有缓存问题）。

### 图谱没更新，怎么查

页脚那个「生成于 …」读的是 `dist/graph.json` 里的 `meta.generated`，也就是**最后一次成功
`build` 的时刻**，不是文件的修改时间。它停在过去，按这四步查（从外到内）：

| 症状 | 查什么 | 怎么判断 |
|---|---|---|
| 页脚时间是几天前 | `schtasks /Query /TN "Knowledge Graph Auto Sync"` | 报「错误: 系统找不到指定的文件」= **计划任务从未注册**，所谓「后台每 30 分钟重建」根本没在跑。用上面那条 `/Create` 命令注册 |
| 任务在，但**从来没跑过** | 任务 XML 的 `<Settings>`：`schtasks /Query /TN "Knowledge Graph Auto Sync" /XML` | 看到 `DisallowStartIfOnBatteries=true` 而机器正在**用电池**（笔记本）= 任务被电源条件挡住。`/Create` 默认就会写这两条，症状极像「跑成功了」：`/Run` 返回「已尝试运行」、属性里 `上次结果: 0`，但进程根本没起、日志一行不写。用下面那段 PowerShell 关掉 |
| 任务在，日志却不动 | `sync-graph.log` 的最后几行 | 末行时间就是上次成功重建。看到 `skip` 说明 `sync-graph.lock` 残留（上一次被强杀/断电），把 lock 文件删掉即可 |
| 日志写 `sync FAILED: python not on PATH` | Python 安装 / 计划任务的环境 | 脚本第一件事就是确认 `python` 可执行；没装 Python 或 PATH 里没有，它直接退出、什么都不建 |
| 日志是新的，页面还是旧的 | 浏览器 | 页面是双击那一刻读进内存的快照，重建不会热更新 —— 关掉标签页重新双击 `dist/knowledge-graph.html` |

上表第二行那段修法（PowerShell 里跑一次即可，改完不用重建任务）：

```powershell
$t = Get-ScheduledTask -TaskName "Knowledge Graph Auto Sync"
$t.Settings.DisallowStartIfOnBatteries = $false   # 电池上也要跑
$t.Settings.StopIfGoingOnBatteries     = $false   # 拔电源也别中断
$t.Settings.StartWhenAvailable         = $true    # 睡眠/关机错过的点，醒来补跑
$t | Set-ScheduledTask
```

另一个常踩的：`python build.py` **不带子命令时默认只跑 `scan`，不写 `dist/`**。
想更新图必须显式 `python build.py build`（子命令有 `scan` / `suggest` / `build` / `verify` /
`watch` / `scope`，不带 `--scope` 时都是 private 那份）。

> ⚠️ **改这两个 `.ps1` 时要留意编码**：`sync-graph.ps1` 和站点那边的
> `quartz-setup\sync.ps1` 都必须存成**带 BOM 的 UTF-8**。Windows PowerShell 5.1 读没有 BOM 的
> `.ps1` 会用系统 ANSI 代码页解码：非 ASCII 字节一旦落在**字符串字面量**里，引号配对就被打乱、
> 直接解析失败（`字符串缺少终止符` / `缺少右"}"`，报错位置还会指到别处），而计划任务会静默停摆
> ——日志一行不写。两个脚本现在都刻意把**消息写成英文**（中文只留在 `#` 注释里），
> 所以就算 BOM 哪天被编辑器剥掉，最坏也只是注释变乱码、脚本照跑。新加日志消息请照样写英文。

## 3. 图里画什么

### 节点：一律实心圆

所有层级（文件夹 / 笔记 / 标题）都画成**实心圆**，靠三个视觉变量区分：

| 变量 | 含义 |
|---|---|
| **颜色** | 所属顶层学科（`theme.domains`：private 的 6 个学科 + public 的第三个根 `Study log`，另有灰色 fallback） |
| **大小** | 规模：目标半径 ∝ 子树叶子数 ^ 0.5，再自顶向下按 `min(装得下, 父子看得出差别)` 等比缩放 |
| **白色描边** | 掌握度 1–5（越粗越实=越熟）；`0` = 未标注，只有暗色细边 |
| **黄色光晕** | 搜索命中 |

之所以全用实心圆：用户是靠 ctrl+滚轮缩放在层级之间穿行的，不同层级的内容本来就靠淡入淡出
区分，再叠加「方框=文件夹、圆=笔记」的形状编码是冗余信息，只会让密集层更难读。
（父层的圆在孩子浮现后会退化成压暗的底图，那是 §4 的五趟绘制，不是另一套形状编码。）

父子同色（都继承所属学科的 domain 色），靠 `mixWhite(0.4)` 的白描边把界线分出来 ——
否则一片同色糊。

### 边：只画「连接」，不画「包含」

- **语义边（细线）**：前置 prerequisite（灰，带箭头）／引用 derives（蓝，带箭头）／
  并列对比 contrast（橙虚线，无向，两端都只有圆点）。示例快照 build5 = 2026-10-16 23:02 下 97 条语义边
  **全是 derives** —— prerequisite / contrast 还没有任何一条写进 `annotations.yaml`（§6.1）。
- **heading → heading 的链接是真边**：`[[Calculus#二阶常系数非齐次微分方程的通解求解步骤]]`
  会精确连到 Calculus 笔记里那个标题节点上（private 那份 build5 快照：68 处命中、14 处锚点未命中，见 §10）。
- **端点标记：线画在哪儿 = 从谁到谁。** 每条边在**两端各截断** `lod.edge_trim_clearance`
  像素（默认 2），线不再插进圆心里；短于 `lod.edge_marker_min_len`（默认 20 像素）的边
  整条不画（线也不画），免得密集层糊成一团。画得出来的边按 `•———▶` 收尾：
  **源端总有一个圆点**（= 出发点），derives / prerequisite **另在目标端画箭头**（= 指向处），
  contrast 是无向关系所以两端都只有圆点；
  标记颜色 = 边色向 `#d6dbe4` 按 `lod.edge_marker_tint`（默认 0.55）混白（`MARK_RGB`），
  比线本身亮，所以压在底图 wash 上也认得出。标记**单独一趟**画在 `drawNodes(front)` 之后、
  `drawEmphasis` 之前（§4）—— 画在节点之前的话，packing 相切的邻圆会整个盖掉它。
  焦点模式下热点边的标记 alpha 抬到 ≥0.75，冷边（压到 7%）基本看不见标记，这是有意的。
  粗尺度下聚合模式（`agg`）的边端点是**祖先代表圆**，箭头指向祖先而非笔记内部的真正标题，
  这是设计如此（§4「跨层级链接怎么办」）。
- **两种连线画法**：顶栏「连线」下拉框切换，选择记进 `localStorage`（键 `kg.edgeMode`，
  private / public 两份共用）。图例说明跟着模式换 —— 两种画法里「线宽」的含义完全不同，
  共用一份图例会误导。
  - **逐条链接（`raw`，默认）**：每处 `[[链接]]` 各画一条细线，**任何缩放尺度都在**。
    缩放只改线的**长度和形状**，不改颜色、不改浓淡、不减少条数 —— 链接本来就是从一个标题
    指向一个标题的，不该因为缩小而消失。同一对元素之间**线的条数就是关联强度**：缩到文件级
    时两篇笔记之间那一束细线，就是它们互相引用的分量（示例快照 **2026-10-16 23:02**：home
    视角下 raw 画 96 条、agg 只画 22 条；最深那一档 agg 归零而 raw 仍有 12 条）。线宽恒为
    `lod.raw_edge_width`（1.0 px，不随缩放变），每条都是**直线**、不做扇形偏离 —— 真实端点
    本来就散在父圆内部的不同位置，一束线天然散开。颜色按**粒度**分：近白
    `theme.note_edge`（`#E6EDF3`）= 整篇级链接 `[[笔记]]`，彩色 = 标题级链接 `[[笔记#标题]]`
    （按关系类型着色）；同一对元素之间的整篇级与标题级链接**都画出来**，靠颜色区分。

    端点**恒为这条链接真实的两个元素自己**，绝不沿 parent 链上移到祖先圆。所以缩小之后，
    那条线的端点可能落进父级圆的**内部**，看着像「线穿进了大圆、没接到圆周上」——
    **这正是想要的暗示**：这里面还有更深的知识点，放大就看得见。每条线都是**直线**，
    不再排扇形：同一对元素之间的多条链接会重叠成一束，放大即可逐条查清。

    **`raw` 下「任何缩放尺度都在」只剩一条边界，而且是纯几何的**：线段短于两端屏幕半径之和
    时无笔可落（`drawRawSegment` 里的 `glen < 0.5`）。它只在两个元素贴得极近时发生，
    **放大立刻恢复** —— 与下面 agg 那三条「越缩放端点越搬、永远追不上」的性质完全不同。
    另外 raw 仍保留一道语义门：真自链接（一个元素链到它自己）不画。
    端点圆自己不画时（没淡入浮现、或被平移出屏），**从它出去的细线照画不误**。

    **下面三条边界是聚合模式（`agg`）专属的**，都是设计如此、不是 bug。agg 里「线画在哪两个
    点之间、这一帧到底画不画」由**端点圆此刻在不在屏上**决定（机制见 §4「跨层级链接怎么办」
    与 §10「侧栏里有某条边、画布上却没有线」）：

    1. **平移同样会换端点代表，不只是缩放。** 端点是否「在屏」的第一道门就是视口裁剪
       （`render.js` 的 `CULL_MARGIN`）：一个圆被平移到整圆出屏，就等于「没浮现」，与它有关的
       每条线都会沿 parent 链上移到第一个**既已浮现、又还没大到铺满视口**的祖先圆上
       （`resolveAnchor`，可能一次跳好几层）。所以按住方向键平移画布，你会看到同一批细线的
       出发点从一个标题换成它的上级标题 —— 线还在、条数也没变，变的只是端点。
    2. **两端塌到同一个代表圆上时，这一帧不画。** `aA.node.id === aB.node.id` 就直接跳过：
       包含关系已经由嵌套圆表达过了，再画一条从圆到自己的线只会糊成一团。
    3. **一整条 parent 链都在屏外时，这条线彻底不画**，因为找不到屏内的附着点。这种情况
       **只有你点选了它的一端**才有兜底 —— 那时 `drawFocusEdges` 会把线画到视口边、挂上朝外
       箭头和写着屏外端点名字的 chip（§3）。**纯缩放、纯平移都没有这个兜底**（`panBy` 刻意
       不动 `selectedId`，hover 也不触发）。chip 本身两种模式都有，只是含义不同：**agg** 补画
       的那条线止于视口边缘，chip 是这条线的终点名牌；**raw** 的线本来就一路画到屏外，chip
       只补上「它指向谁」这个名字（由 `drawRawEdges` 主循环挂，不经 `drawFocusEdges`），
       而且**两端都出屏时也照挂一枚**（名字给非焦点的那一端）—— 所以 raw 下平移换不出这个
       兜底，上面第 3 条那个「彻底不画」只属于 agg（§10）。

    换句话说：在 **agg** 下「缩小/平移之后那条箭头不见了」几乎总是端点上浮到了父标题
    （第 1 条），而不是链接被丢掉了；在 **raw** 下那条线就在它真实的两个元素之间，看不见
    只可能是它整条落在屏幕外。想确认某条具体链接在不在，**别数 `KG.state().shownEdges`** ——
    那是全局计数，会随视口剧烈变化；点选它的一端看侧栏边行，或点边行让 `fitPair` 把两端
    一次框进屏幕。
  - **按尺度聚合（`agg`）**：当两篇笔记之间有很多条标题级链接时，在较粗的层级上它们被
    合并成「各自祖先之间的一条边」，**线宽 = 被合并的原始链接数**。这就是跨层级链接的
    处理方式（§4）。
- **包含关系不画成网状线**：嵌套圆布局本身就在表达包含。hover 或选中某节点时，
  才用**点线**（`setLineDash([1, 4])`，圆头，alpha 0.35）画出它的祖先链，并在侧栏顶部
  给出面包屑。刻意做得比链接线更轻：点线是「你在哪」，实线才是「谁链接谁」，
  两种线混在一起会让人以为祖先链也是链接。
- **焦点模式：选中即过滤连线。** 全部连线一起画太乱，所以单击选中一个节点后进入焦点模式：
  只保留与它**或它内部子元素**相关的连线（链接出去、链接进来都算）并加粗，
  其余连线压暗到 `lod.focus_edge_dim`（默认 7%，改成 0 即彻底不画）；
  与它相连的其他元素圆周亮**蓝色光环**（`#4c8dff`，与搜索命中的黄环区分）。
  无关节点**不**压暗也不隐藏 —— 圆是底图（地图上的「省」），压暗会摧毁方位感；
  这也是与 Obsidian graph view / Cytoscape 常见配方的有意分歧。
  `Esc` / 单击空白 / 双击空白退出焦点模式、恢复全部连线。
- **焦点边的屏外端点兜底：视口边箭头 + 名字 chip。** 选中元素后，若某条相关链接的一端
  在当前尺度下落在屏幕外（还没淡入浮现、或被平移出视口），这条链接不会被默默丢掉：
  连线**止于视口边缘**，止点处挂箭头/圆点指示方向（箭头 = 屏外那一端是被指向的），
  旁边再挂一枚写着**屏外端点名字**的小 chip（超过 18 字截断）。chip 同时最多挂
  `lod.focus_offscreen_chips` 枚（默认 8），超出折叠成右下角一枚 `+k`。**chip 只指示方向
  与名字，点击无行为**；要导航去另一端，点侧栏入边/出边列表里对应的边行——相机会一次
  动画把链接两端一起框进屏幕，连接箭头直接可见。**两端都在屏外时按模式分开**：`agg` 这条
  链接当帧不画、也不挂 chip（没有屏内附着点）；`raw` 只要线段横穿视口就照画，并且**也挂
  一枚** chip，名字给**非焦点的那一端**（见 §10）。

## 4. 语义缩放与淡入淡出（核心机制）

**方向：滚轮向上 = 放大 = 看到更深的层级**，和地图软件一致。

这个方向是布局的**几何构造**，不是靠补丁凑出来的：circle packing 下子圆严格落在父圆内部、
且半径一定更小（父半径 ≥ 最大子圆 × `layout.level_ratio` = 1.5），所以沿任何一条包含链，
世界半径 `r` 严格递减 ⇒ `minzoom` 严格递增 ⇒ 孩子永远比父母更晚浮现。

### 每个节点自己决定何时浮现

构建期给每个节点算一个世界半径 `r`（= 它在知识树里占的地盘），渲染期：

```
minzoom = lod.min_px / r               # 屏幕半径达到 min_px 像素时开始浮现
alpha   = smoothstep(minzoom/fade_span, minzoom, zoom)   # 在 fade_span 倍率带宽内淡入
```

`lod.min_px = 18` 读作「一个圆值得被画出来的最小屏幕**半径**」。它同时决定 `zMin`：
最小学科根在 `zMin` 处恰好是 `min_px × zoom_out_floor`。

所以**淡入淡出是 per-node 的连续过程，不是 per-layer 的开关**。放大时深层节点从各自的
位置逐个「长出来」；因为叶子半径随路径上的累积缩放而分散，浮现被摊开到十几格滚轮上
（单格滚轮最大涌入 10%），不会齐刷刷弹出一片。

父层节点由 `zoom.parent_dim`（0.22）压暗但保留，作为上下文。嵌套实心圆下**父圆填充就是
子圆的「底色」**，压得不够狠会把子圆整体一起压暗；0.22 才留得住「省 = 浅色面、
市 = 清晰界线」的地图层次。

### 五趟绘制（「放大时省淡出、市界淡入」就落在这里）

一帧分五趟落笔，顺序照搬地图软件：

1. **wash（容器底图）**：已经有孩子浮现的圆退化成压暗的填充 + 一条清晰界线 —— 地图里的省
   就是这样，面很淡、界线很清楚，市画在它上面。这一趟还带矢量瓦片的另一半语义 **`maxzoom`**：
   圆一旦铺满视口，它的填充只是一层均匀色罩、界线也退到屏幕外，继续画只会和更外层的罩子
   叠成不透明色块。所以接近铺满时平滑退场、铺满后停画，只留还没铺满的最内层圆当
   「你在哪个区域里」的界线 —— 省界退出屏幕后只剩市界。停画的祖先**仍参与命中测试**，
   点空隙 = 选中所在的「省」。
2. **语义边**：夹在底图之上、实心圆之下 —— 压在底图之上才看得见，被实心圆盖住又正好形成
   「线连到圆边上」的观感。这一趟顺手把线在**两端各截断**几个像素，并把要画的端点标记
   塞进 `markJobs`（只排队、不落笔，理由见下面那段）。
3. **前景实心圆**：当前尺度上最细的那一层，不透明。子盖父（深度升序、同深度大圆先画）。
4. **端点标记**（`drawEdgeMarkers`）：把第 2 趟排好的 `markJobs` 落笔 —— 源端一个提亮圆点、
   目标端一个箭头。**必须**排在实心圆之后：packing 布局里圆是相切的，箭头正落在邻圆边界上，
   先画就被整个盖掉（这是箭头「明明有却看不见」的主因之一，见 HANDOFF §4）；
   又必须排在强调环之前，让选中白环 / 邻居蓝环仍然压过它。
5. **标签**（字号随屏幕半径连续变化，见下面「标签」一节）。

强调环（掌握度 / 搜索命中 / 选中）单独一趟，永远画在最上面。

屏外 chip（`drawChips`）比强调环更靠外：它是**屏幕空间**的 HUD 覆盖层，排在所有世界内容
之后落笔，不算进上面五趟 —— 不参与世界坐标的遮挡关系，所以永远读得到（§3 屏外端点兜底）。

### 标签：字号跟着屏幕半径走（不跟着深度走）

字号不是常数，而是该节点当前**屏幕半径** `_sr` 的函数，在 `lod.label_font_min`(11) 与
`lod.label_font_max`(22) 之间按对数插值：

```
fs = clamp(F_MIN + (F_MAX - F_MIN) × ln(sr / min_px) / ln(ref / min_px), F_MIN, F_MAX)
     # F_MIN = lod.label_font_min = 11      ref = lod.label_font_ref = 300
     # F_MAX = lod.label_font_max = 22      min_px = lod.min_px = 18
```

实测落点（屏幕半径 px → 字号 px）：18→11、27→13、40→14、60→15、100→17、200→20、≥300→22。
另外 `depth ≤ lod.label_bold_depth`(2) 的标签加半粗（600）—— 粗细是「类别」信号，字号是「尺度」信号。

**为什么绑屏幕半径而不绑 `depth`**：packing 布局下半径是内容驱动的（同级里内容多的圆更大），
`depth` 只是树的层数，两者不成正比。最粗视图那 6 个学科根同为 depth-1，世界半径却差 **13.97×**
（Science and Tech 717.82 / Medical and Health 51.38，示例快照 verify6 = 2026-10-17 00:15）；
按 depth 分档会让铺满全屏的根和一枚 20px
的小圆点同字号。屏幕半径本来就是这套 LOD 的度量轴（`minzoom`、圆内/圆外摆放、视口裁剪都读它），
而 `r` 沿包含链严格递减 ⇒ **屏幕半径的大小关系天然就是层级的大小关系**。
对数插值是因为缩放是乘法过程，线性插值会让字号在中间一段涨得太快。
字号**必须取整**：`measure()` 的缓存 key 是 font 字符串，亚像素字号会让缓存失效并撑爆。

字号一变大就得同时管住宽度，否则一条长标题能横扫半屏：

| 标签位置 | 宽度不变量 | 装不下时 |
|---|---|---|
| 圆内（`_sr ≥ 28`） | ≤ `1.8 × _sr` | 用最小字号试算，仍超宽就把标签翻到圆外去挂 |
| 圆外 | ≤ `lod.label_max_width`(180px) | 先逐级缩字号到 `label_font_min`，还超宽就二分截断加 `…` |

截断只影响画布上的那行字：hover 气泡与搜索用的都是完整 `name`，信息没丢。
圆内标签压在圆的**顶部内侧**（`sy = 圆心y - _sr + fs/2 + 4`），任何字号下文字上边界都离圆描边
2px，所以换字号不会让文字骑到描边上。

标签的不透明度读 `fillAlphaOf`（与圆填充同一条连续曲线，`lod.label_smooth_dim` 可关），
门槛是 `lod.label_alpha`(0.12) —— 为什么门槛这么低、为什么不能用最终 alpha，见 §8 第 9 条。


### 跨层级链接怎么办（这是你问的那个疑惑）

地图软件处理「北京到上海的高铁」时，在省级图上是两个省会之间一条线，在市区图上是两个
车站之间一条线。它用的是**两层机制叠加**，本项目的聚合模式照搬：

1. **层级预聚合（generalization）** —— 构建期已算好 `aggregates[L]`：任意两个元素之间的
   关系，在第 L 层表现为「各自在第 L 层的祖先」之间的一条聚合边。所以一条 heading→heading
   的链接**在每个尺度上都有一个唯一确定的代表**，不需要在渲染期临时决定端点。
2. **per-node minzoom** —— 就是 Mapbox vector tile 里那个 `minzoom` 字段，由节点自己的
   世界半径 `r` 决定。端点自己决定什么时候浮现，**边的 alpha 直接取两端点 alpha 的最小值**。

于是：「这条边现在画在哪两个点之间」由 (1) 决定，「它现在该不该出现、多透明」由 (2) 决定。
**边本身不做独立的淡入淡出——那是它两端点的事。** 两端都在淡入带里时，边跟着一起淡。

上面 (1)+(2) 是**聚合模式（`agg`）**。默认的**逐条模式（`raw`）(1) 和 (2) 都不用**：

+ 它不查 `aggregates[L]`，也**不沿 parent 链找「在屏代表圆」** —— `resolveAnchor()` 只服务
  agg；raw 走 `rawAnchor()`，端点**恒为这条链接真实的两个元素自己**，任何尺度都不上移。
+ 它的 alpha **恒为 1** —— 不乘端点淡入进度、也不乘「count < `WEAK` 打 45 折」的弱边折扣
  （那两项都是 zoom 的函数）。所以缩放**不改颜色、不改浓淡**，只改线的长度和形状。
+ 每条原始链接各画一条**直线**、条数不减：缩小看到的不是「一条更粗的线」，而是「一束细线」，
  束里几条就是关联强度。真实端点本来就散在父圆内部的不同位置，一束线天然散开，不需要
  agg 那种扇形展开。
+ 端点圆自己不画时（没浮现、或被平移出屏），线照样从它的世界坐标出发，于是粗尺度下会看到
  线**穿进**父级圆内部 —— 这正是「这里面还有更深知识点」的暗示。

代价是落笔数明显变多（示例快照 **2026-10-16 23:02**：home 视角 raw **96** 条 / agg **22** 条），
所以两种画法都留着，由顶栏下拉框选（§3「边：只画连接，不画包含」）。

### 换层与跳层

- **层级胶囊**（顶栏 1..10）点一下就跳到那层；**`[` `]`** 逐层换；
  **`zoomToDepth(d)`** 是控制台入口。
- 每个层级有一个 `enter[L]` 缩放值（= 该层 minzoom 中位数沿深度取前缀最大），
  它只用于两件事：HUD 上「第几层」的读数、以及跳层的相机目标。它**不**反过来给节点封顶 ——
  一个内容特别多的子圆 minzoom 低于本层中位数是正确行为，它本来就该更早被看见。
- **zoom 是唯一真源**，层级读数由 zoom 单向派生，所以不存在「视角收窄 → zoom 变大 →
  又跳回深层」的正反馈震荡。
- **双击空白处**回到 home 视角（实测停在**第 1 层**，`home_zoom = 0.4612`，
  由 `zoom.home_fit` = 1.08 决定；它的硬上限是 `layout.padding` = 1.12，
  再大就会把 Science and Tech 裁出屏幕）。
- 落在没有内容的地方时（两个方向都可能 —— 缩太远、或放大到 maxzoom 停画），画布上有兜底
  提示文字，`Home` / 双击空白 / 顶栏「重置」都能一键回到 home 视角（见 §5、§10）。
  判据是 `stats.painted`（真的落了笔的节点数），**不是**候选集大小 —— 用错就会「画布全黑
  却没有任何提示」（这条坑见 HANDOFF §4 坑 33）。

| 操作 | 效果 |
|---|---|
| ctrl + 滚轮 / 滚轮 | 连续缩放（光标处锚定，`zoom.wheel_step = 1.12`，走完 10 层约 45 格）。**滚轮不再被 `zMin` / `zMax` 夹住** —— 那两个是地标不是墙，缩过头画面会渐渐清空，见下面「缩丢了怎么办」 |
| `[` `]` | 换到更粗 / 更细一层（这一对仍然夹在地标内，跳层是「工具自己去某个地方」） |

| 拖拽 | 平移 |
| `方向键` | 平移（一步 = 视口宽的 1/8，按住 `Shift` = 半个视口，约 4×）。**刻意不碰选中态**：拖拽时一次不到 5px 的抖动会被判成点击（`render.js` 的 `dragMoved > 5`），选中就切到光标下那个大父圆上、焦点模式随即把想看的箭头滤掉；方向键把「平移」与「点击」解耦 |
| 双击空白处 | 回到 home 视角（depth 1） |
| `Home` | 回到 home 视角 —— 与双击空白、顶栏「重置」按钮同一个入口（`resetView()`）。两头缩丢了就按它 |
| 单击节点 | 右侧详情栏：面包屑、掌握度、入边、出边、标题清单；**同时进入焦点模式**（§3：只留下与它相关的连线并加粗，其余压暗到近乎消失，相连元素亮蓝环） |
| 悬停 | 气泡（标题、所属、掌握度、摘要）+ 画祖先链点线（`[1, 4]`，与链接实线区分） |
| 搜索框 | 命中节点加黄色光晕，点结果直达并换层 |
| 学科 / 掌握度下拉 | 过滤 |
| 标签下拉 | 自动（默认，按屏幕密度竞争）／全部显示／只显示选中 |
| 侧栏入边/出边的边行点击 | 相机一次动画框住这条链接的两端（`fitPair`）；一端当前在屏外也能到了就直接看见连接箭头 |
| 侧栏「在 Obsidian 打开」 | `obsidian://open?…` 跳回 Obsidian |
| `Esc` | 取消选中并恢复全部连线 |

**缩丢了怎么办。** 缩放上下限放开之后，画布会出现空视口，两个方向都可能：

- **缩得太远**：屏幕半径掉到 `lod.min_px` 以下，圆一个个淡出，最后连世界半径 1000 的根也没了
  （示例快照 bc6 = 2026-10-17 23:05：默认那份实测要**往下滚约 27 格**；公开那份 18 格，
  它的 `zMin` 更低）。
- **放得太大**：圆只是继续变大，标签字号早就饱和（撞 `lod.label_font_ref`）；再往深处会撞上
  本来就有的 **maxzoom** 规则（圆的屏幕半径达到「圆心到视口最远角」就停画填充），视口一样会空。
  `zMax` **不是**这条边界：bc6 那批**两份同档 z = 472.2**（默认那份约 **6.8× `zMax`**、
  公开那份约 **6.9× `zMax`**）。bc5 那批公开那份还**更晚**（约 **27.3× `zMax`**，z = 1888.9），
  bc6 已经同档 —— 空在哪一档取决于 payload 的形状 + 当批快照，别当常数。

两种都会画出「此处没有内容」的兜底提示，**都不是崩**。找回手段有三个：`Home` 键、双击空白、
顶栏「重置」——三者都走 `resetView()` 回 `zHome`。

兜底提示的判据是 **`stats.painted`**（真的按 `PAINT_MIN`(0.02) 落了笔、且几何上穿过内容视口的
节点数），**不是**候选集大小：候选集里可以有一个圆心远在屏外、半径极大的圆 —— 它的填充被
fade 压到看不见、界线弧又整条落在画布之外，于是 `stats.nodes ≥ 1`、画布上一个像素都没有。
拿 `stats.nodes` 判就会出现「一片漆黑且没有任何提示」的死局，**这条本轮真的踩到过**
（公开那份 z ≥ 5000 时整块画布 0 个非背景像素）。见 HANDOFF §4 坑 33。

**「我在笔记里加了个标题，会自动出现在图里吗？」会。** 标题层是每次构建时从正文实时解析的。
重建方式见 §2。

## 6. 给图谱加语义：三种方式

### 6.1 `annotations.yaml`（推荐，手工但集中）

不用往 111 篇笔记里塞 frontmatter（篇数是 private 那份的示例快照 verify6 = 2026-10-17 00:15 读数），
全部标注集中在一个文件里：

```yaml
notes:
  "模拟集成电路":
    weight: 5          # 重要度，影响节点大小
    mastery: 3         # 掌握度 1-5，影响白色描边
    aliases: ["模电"]  # 让 [[模电]] 也能解析到这篇
edges:
  - source: "MOSFET"
    target: "模拟集成电路"
    type: prerequisite  # 或 derives / contrast
    weight: 3
    reason: "模电第一节课就是 MOSFET 的小信号模型"
```

优先级：`annotations.yaml` > 笔记 frontmatter > 自动推断的 wiki 链接
（`config.yaml` 的 `precedence` 可以翻转）。

### 6.2 笔记 frontmatter（可选）

支持 `prerequisites` / `derives` / `contrasts` / `mastery` / `weight`。写了就生效，不写不影响。
`parent` / `subject` / `domain` 只作为显示信息，**不会**改变层级归属。

### 6.3 `candidates.yaml`（自动挖掘 + 人工审核）

`python build.py suggest` 离线挖掘候选边，每条带得分、类型、理由：

```yaml
candidates:
  - source: "半导体物理(大三上)"
    target: "半导体物理(大二下)"
    type: contrast
    score: 0.99
    reason: "共享术语：junction、impurity…；两篇笔记都含有同名标题，疑似同一门课的不同版本"
    status: pending
```

把想保留的 `status` 改成 `accepted`，再 `python build.py build`。`pending` / `rejected` 都不进图。
**重跑 `suggest` 会保留你已有的审核结果**，不会把 accepted 打回 pending。

三条启发式：标题与笔记同名（→ 前置）／英文术语与 LaTeX 符号的逆文档频率共现（→ 并列）／
同名标题跨 3 篇以上笔记（→ 疑似重复笔记）。中文不分词——不引入 jieba 这类重依赖，
中文侧只做标题精确匹配，宁缺勿滥。

## 8. 关键实现决定（维护时先看这里）

1. **单文件必须全内联。** Chrome 在 `file://` 下禁止 `fetch`/XHR 读本地文件，
   HTML 一旦去 fetch `graph.json`，双击打开必然失败。数据与全部 JS/CSS 都内联。
   代价是约 8.7 MB（示例快照 2026-10-17 00:07：8957 KB），但换来「双击即用」。

2. **坐标一次算定，缩放只改可见性。** `layout.py` 用 circle packing：深度 = 嵌套层数，
   规模 = 圆半径，子圆严格落在父圆内部、兄弟圆互不相交。半径分两步定 —— 目标半径
   ∝ 子树叶子数 ^ `layout.size_exponent`(0.5)，再自顶向下按 `min(装得下, 父子看得出差别)`
   等比缩放。private 那份的六个学科根世界半径 `r` 依次是
   717.82 / 170.41 / 88.99 / 74.30 / 69.28 / 51.38（示例快照 verify6 = 2026-10-17 00:15），spread **13.97×**；
   `layout.norm_root_radius`(1000) 把坐标量级钉住，JSON 体积可控、
   zMin/zMax 不随 vault 增长而漂移。渲染期**不做任何布局计算**，所以缩放时节点永不跳动。
   `verify.py` 断言「切层前后坐标零漂移」。
   （这些数值随笔记增删漂移，不是不变量；`verify` 的输出才是当前读数。）

3. **布局必须与地图同构，`minzoom` 才能直接照搬。** 地图把细节编码成**尺度**：放大后同一块
   地物变大、露出更多细节。同心环把深度编码成**半径**，两者不同构 —— 那个模型里半径只能
   用来分圈，压根不携带子树规模的信息，于是「放大 = 更深」只能额外叠一层 per-depth 封顶
   硬补回来，而且同一圈上所有节点一样大、「子元素落在父元素内部」几何上不可能。
   circle packing 才同构：深度 = 嵌套层数，规模 = 圆半径，缩放到哪一层就看见哪一层。
   所以 `minzoom` 可以直接用 Mapbox vector tile 的语义，不需要任何按深度的门控补丁。

4. **半径的两条规则都是被逼出来的，别再往回改。**
   * **分档是「包含式」的，不是「全局按深度」的。** 若强行要求任意 depth-L 的圆都大于任意
     depth-L+1 的圆，那每层**最小**的圆（叶子）必须大于下一层**最大**子树的打包半径；
     自底向上递推每层要 ~3–4× 膨胀，10 层累积 **10⁵~10⁶ 倍**半径比，需要 **100+ 格滚轮**
     才能从最外层走到最内层 —— 完全不可用。`layout.level_ratio`(1.5) 保证的是「父圆明显
     大于它的孩子」，这才是「文件夹 > 其内笔记 > 其内标题」能落地的读法。
   * **半径自顶向下分配，不是自底向上打包。** 「节点半径 = 子圆打包后的包围圆」会让半径随
     叶子数近乎线性增长：六个学科根的叶子数从 **11**
     （Medical and Health）到 **2147**（Science and Tech），spread **195.2×** —— 任何一个能让
     最小根看得清的 zoom，都会让最大根冲出屏幕近 200 倍远。自顶向下 + 固定指数 0.5 把 spread
     钉成 (2147/11)^0.5 = **13.97×**（实测根 `r` 717.82 / 51.38，示例快照 verify6 = 2026-10-17 00:15，逐位吻合）。
     `size_exponent = 0.5` 还是个无标度不动点：√(Σ Tᵢ²) = √(Σ Lᵢ) = T_parent 精确成立，
     每层缩放因子退化成与分支数无关的常数 ≈0.85。
     （旧读数，未随本次快照重跑：叶子数 11 / 2147 与 spread 195.2×（`verify.py` 不打印叶子数）、
     等效指数 L^0.83~L^0.95、自底向上打包 spread 79.6×；
     `size_exponent` 调到 0.6 时 spread 升到 28.3×、最小学科在 home 只剩 18.2px ——
     要重跑得另建替代布局。）

5. **`r` 沿包含链严格递减，`minzoom` 因此严格递增 —— 这是几何性质，不用人为维护。**
   子圆严格在父圆内部且半径更小，「子节点不会比祖先先浮现」自动成立，`verify.py` 实测
   违反 0 个。（旧版得靠一个专门的补丁函数把间距沿包含链取前缀最小值才守得住这条。）

6. **密度账：同屏圆数有常数上界。** 浮现的圆两两不相交、屏幕半径都 ≥ `lod.min_px`，
   所以同屏圆数 ≤ (视口半径 / min_px)²，与 vault 多大无关 —— 示例快照 bc6 = 2026-10-17 23:05 下
   这一轮上滚扫描（每 6 格取样）里同屏最多 **168** 个（默认那份，50 格）/ **135** 个（公开那份，58 格）。
   同心环时代这笔账无解：第 6 圈 939 个节点整体适配视口时只剩 2.7px 间距，
   任何半径、任何 `angle_power` 都改不了；packing 下这 939 个节点**不会被同时要求浮现** ——
   它们分散在各自的父圆里，只有放大到对应父圆时才出现。同理，同心环时代所有叶子半径相同
   ⇒ minzoom 相同 ⇒ 叶子会在同一格滚轮里齐刷刷弹出（单格涌入 66%），packing 下叶子半径
   随路径累积缩放而分散，单格最大涌入降到 10%。

7. **`<canvas>` 是替换元素**，CSS 必须写 `width:100%; height:100%`，
   同时 JS 里设 `canvas.width/height` 为设备像素，两者缺一就会模糊或尺寸错位。

8. **相机 tween 每一帧都必须回调 `onCamera`**，否则动画期间画布不重绘，看起来像卡死。
   `browser_check.py` 用「连续两帧快照比对」来收口这类问题。

9. **标签门槛读的是「未压暗的淡入进度」，不是最终 alpha**（`lod.label_alpha` = 0.12）。
   祖先层被 `parent_dim` 压到 0.22 之后就永远够不到高门槛，
   结果最粗的视图（最该有标签的视图）会一个标签都没有。这是个踩过的 bug；
   现在门槛压到 0.12（几乎「一浮现就有资格竞争标签位」），真正决定谁写出来的
   是 24px 碰撞网格 + 400 个候选上限。
   配套地，标签**落笔浓度**改读 `fillAlphaOf`（开关 `lod.label_smooth_dim`，默认 true）：
   原先读 `alpha.get()`，节点越过 `_gate` 那一刻会从 ~1.0 瞬跳到 `parent_dim`，
   观感是「啪」地变暗而不是淡出。候选**排序**仍读 `alpha.get()` ——
   排序要的是稳定优先级，落笔要的是连续过渡，这个不对称是有意的。

10. **`parse.py` 有意不排除行内代码里的 `[[Foo]]`。** 笔记里用 `` `[[Foo]]` `` 举例时
    确实会产生一条假链接，但排除行内代码会连带干掉大量正文里合法的链接写法，
    权衡后保留，宁可多一条弱边。

## 9. 校验

> **本节所有绝对数字都是某一次 payload 的「示例快照」**，快照时间 = `dist/graph.json` 的
> `meta.generated`（本节各处的戳不统一，分属下方那张**批次表**里的四批）。计划任务每 30 分钟重建一次 `dist/`，
> vault 内容一改这些数就漂 —— **任何绝对数都不要当不变量写进断言或记进脑子**。要复现就现跑：
>
> ```bash
> python build.py verify                  # 数据侧，private
> python build.py verify --scope public   # 数据侧，公开那份
> python browser_check.py                 # 浏览器侧
> ```
>
> 下面每处标了「示例快照」的数字都按这个口径读；少数标了「旧读数」的是**没随本次快照重跑**
> 的历史数字（重跑需要另建替代布局或另做人工实测），只当量级参考。
>
> 漂得有多快，有两个现成的例子。第一个：写这一节时 `dist/` 已经被计划任务重建过好几批
> （**09:37 → 10:07 → 10:37**），起因只是 vault 里一次笔记改名（`电路分析基础.md` →
> `Basics of circuit analysis.md`），语义边就从 99 / 98 变成 97 / 96、标题级链接从 69 变成 68。
> 第二个更说明问题：本节定稿后过了一夜，`dist/` 又被重建（**2026-10-18 12:37**），语义边再变成
> **98 / 97**、标题级链接 **69**、节点 3559 / 3519、depth≤10 边 3651 / 3613、聚合边 3837 / 3799 ——
> 起因只是 vault 里多写了一个 depth-4 的标题（标题级别分布 `4: 605→606`）。`zMin` / `zMax` / `enter[]`
> 一格没动，两份 verify 仍全绿。也就是说：**代码一行没改，本节所有绝对数就都对不上你屏幕上的了。**
>
> 所以本节数字一律钉在某一批快照上、并注明生成时间，**不追着最新一次重建重测**：
>
> | 来源 | 快照批次 | 生成时间 |
> |---|---|---|
> | `build.py build --scope all` | build5 | **2026-10-16 23:02** |
> | `dist/` 尺寸 | 计划任务重建（与 build5 逐字节同尺寸） | **2026-10-17 00:07** |
> | `build.py verify` | verify6 | **2026-10-17 00:15** |
> | `browser_check.py` | bc8 private **162 `[ok]`**（2026-10-18 22:46）/ bc7 public **162 `[ok]`**（2026-10-18 22:42），各 0 `FAIL`、2 `WARN` | **2026-10-18 22:46** |
>
> 前三批是同一份数据（`nodeCount` 3558、`zMax` 68.9753、`enter[10]` 39.956、语义边 97 / 96 逐位吻合），
> 中间 00:07 那次重建没有改动数据。上面两处漂移（99 / 98 / 69 与 98 / 97 / 69）分别是快照**之前**和
> **之后**的值，都保留在这里当漂移的标本。`browser_check.py` 那批**换过 payload**：它跑在
> build7（**2026-10-18 22:25**）重建的 dist 上，绝对数与前三批不同源，只有「全绿 / 0 FAIL /
> 162 ok」这类结构性结论可以跨批比对。

### `python build.py verify`（数据侧）

不带 `--scope` 时校验 private 那份（`dist/graph.json`）；`--scope public` 校验公开那份。
两份都全绿。示例快照 **2026-10-17 00:15** 下 private 的读数：

- 深度轴 10 层，每层节点/边数与 `levels` 一致
- 所有边两端都存在；附件没有被当成节点；链接解析统计完整
- **节点与 scope 声明对齐**：depth=1 的根 == 该 scope 声明的目录（private 6 个 / public 3 个）；

## 10. 已知限制

前四条是布局的固有行为，**不是 bug**：

- **深缩放时可能只看到「区域界线弧」而没有可点节点**：那是 wash 趟里已经铺满视口、
  停画填充但仍描边的父圆边界（§4）。
- **落在无内容处会显示兜底提示**「此处没有内容 · 往回滚一点，或按 Home / 双击空白回到默认视角」，
  **同时 tooltip 仍显示所在的「省」** —— 命中测试有意保留已停画的祖先，
  点空隙就是选中所在的那个区域，和地图上空白海域也标省名是一回事，别去「修」它。
  措辞故意两个方向都管用：**缩放上下限是地标不是墙**（§5「缩丢了怎么办」），
  空视口既可能来自「缩得太远」（要往回滚），也可能来自「放得太大撞上 maxzoom」
  （也要往回滚，只是含义相反）。老文案只写「向下滚回到更粗的层级」，在缩太远那一侧是反的。
  提示本身的判据是 `stats.painted`（真的落了笔的节点数），**不是**候选集大小 —— 用错就会
  「画布全黑却不提示」，见 §5 与 HANDOFF §4 坑 33。
- **独子链会出现父子同心**（坐标重合的 351 对全是这种），靠 `level_ratio` 1.5 的半径差
  + `mixWhite(0.4)` 描边区分，不会塌成看不出的靶环。
- **半径不是「绝对内容量」的函数，而是「相对父节点分到的份额」**：深层同叶子数的两个节点
  半径可以差几倍，取决于各自路径上的累积缩放。这是有意为之 —— 这张图要保证的是
  **包含关系**（文件夹 > 其内笔记 > 其内标题）与**同级相对大小**（同层里内容多的更大），
  这两条都完整保留；跨分支比较绝对大小从来不是它的读法。

连线可见性还有两条固有行为，也**不是 bug**：

- **侧栏里有某条边、画布上却没有线：门叠加的结果，而门数随模式变（`raw` 一道 / `agg` 三道）。**
  侧栏入边/出边列表读的是原始边表，没有尺度概念；画布上这条链接要在当前尺度画出来得过门。
  **默认的逐条模式（`raw`）只有一道门，而且是纯几何的**：整条线段的屏幕 bbox 与内容视口
  不相交才不画。端点恒为真实的两个元素自己、绝不上移，所以「端点圆没淡入浮现」「端点圆被
  平移出屏」都**不**影响这条线画不画 —— 这正是「链接不该因为缩小而消失」的落点（示例快照
  **bc6 = 2026-10-17 23:05**：默认那份最深那一档 agg 直接归零、raw 仍画出 12 条）。raw 另有两处
  算不上「门」的边界：真自链接（一个元素链到它自己）没有方向可画；线段短于两端屏幕半径之和
  时无笔可落（`drawRawSegment` 里的 `glen < 0.5`），**放大立刻恢复**。
  **聚合模式（`agg`）有三道门**：两端落在同一个祖先圆里（包含关系已由嵌套圆表达，线不画）、
  任一端点当帧不在屏上（没淡入浮现、或被平移出视口）、聚合索引在这一层没有代表。
  「端点不在屏上」这一道两种模式都有兜底：**agg** 由 `drawFocusEdges` 把线补画到视口边、挂
  朝外箭头 + 写着屏外端点名字的 chip；**raw** 的线本来就由主循环一路画到屏外，chip 挂在它
  穿出视口的那一点上，补的是「它指向谁」这个名字（§3）。
  **两端都在屏外时**：agg 这条链接不画线也不挂 chip（没有屏内附着点，画出来是指向虚空）；
  raw 只要线段横穿视口就照画（线穿过屏幕就该看得见），并且**也挂一枚** chip —— 名字给
  **非焦点的那一端**（选中 A 时答「这条线通向谁」，选中 B 时答「这条线来自谁」；两端同属
  焦点子树时无从区分，退回目标端 B），位置由 `entryToward` 用 slab 裁剪求线段**进入**视口
  的那一点，且要求这一帧真落了笔（`laid`，斜角擦过视口的线不配名字牌）。挂**一枚不挂两枚**：
  线一进一出、方向本来就看得见，两枚只会把真正有用的焦点 chip 挤出 `CHIP_MAX`。
  这一枚补的是「平移一下让选中项整圆出屏、名字牌跟着消失，就再也读不出这条线通向谁」那个洞
  （示例快照 **2026-10-18 22:25**：真实按 5 次 `ArrowLeft` 后 raw 读到 `focusEdges 1 /
  chips 1`、chip 钉在视口上边缘 `[349,0]`，同视角 agg 是 `chips 0`；`browser_check.py` 的
  (a2) 段已把它钉成永久回归）。
  想看某条具体链接，点侧栏对应边行让 `fitPair` 把两端一次框进屏幕。
- **chip 只指示、不导航。** 屏外端点名字 chip 是纯画布 HUD，命中测试只认节点圆；
  点 chip 无任何行为，导航一律走侧栏边行。

以下是数据侧仍然存在的限制：

- **14 处 `[[笔记#标题]]` 锚点未命中**（private 示例快照 build5 = 2026-10-16 23:02）：锚点文本与标题不完全一致
  （Obsidian 的锚点匹配更宽松）。放宽逻辑在 `kg/graph.py` 的 `_normalize_heading()`。
- **中文不分词**，所以「自动发现前置知识」只覆盖英文术语与 LaTeX 符号。
- **正文 `[[链接]]` 的方向语义天然模糊**（A 链接到 B 可能是依赖，也可能只是"另见"），
  统一记作 `derives`。要精确语义请写进 `annotations.yaml`。
- **掌握度描边目前看不到效果**：`annotations.yaml` 里还没标 mastery，
  111 篇笔记（private 示例快照 verify6 = 2026-10-17 00:15）全是 0（暗色细边）。这不是功能缺失。
- **范围真源坏掉时本项目会直接报错退出**（缺文件、缺 `from`、`scopes` 写错、引用未声明的
  scope、目录不存在、同一 scope 里落地名重复……都会给出中文错误信息），**不会静默退回某个
  默认范围** —— 范围这种东西猜错一次就是一次泄漏。`quartz-setup/public-scope.yaml` 就是
  现在唯一的那份定义，站点与图谱共用它。
